# 架构与维护说明

## 分层

```text
MCP 工具 ─┐
          ├─> WorkshopService ─> CampaignStore ─> SQLite
Web API  ─┘          │
                     └─> 骰子、货币、状态与 SRD 目录

React 管理台 ─> Web API ─> 同一 WorkshopService
```

- `mcp_server.py` 只声明工具和参数，不实现业务规则。
- `web.py` 负责 HTTP 状态码、命令白名单和静态前端托管。
- `service.py` 是规则边界。所有状态写入必须由这里进入存储事务。
- `store.py` 负责并发控制、修订号、JSON 快照、审计和撤销。
- `state.py` 定义新状态默认结构，并兼容补齐旧快照字段。
- `catalog.py` 保存可再分发的 SRD 入门数据，不与规则代码耦合。
- `spell_catalog.py` 只读加载用户法术库，负责去重、稳定 ID 和保守解析。
- `spell_rules.py` 集中保存职业别名、法术位、已知/准备与契约魔法规则表。

适配层不得直接修改 SQLite 状态，否则 Web 和 MCP 会产生不同规则行为，并且
绕过审计记录。

## 权威状态与标识

一个战役以 JSON 快照持久化，包含角色、物品定义、法术定义、商店、遭遇、
共享仓库和修订号。实体以 UUID 为主键，名称仅用于展示和搜索。物品定义 ID
描述“是什么”，物品栈 ID 描述“谁持有哪一批”，两者不能混用。

金额统一保存为整数铜币，重量单位为磅。标准负重上限为 `STR * 15`。角色
生命状态由 HP、伤害、治疗和死亡豁免共同维护，`unconscious` 不能作为普通
状态直接写入。

## 外部法术目录

`spells.db` 不属于权威战役数据库。搜索时程序只返回分页摘要，读取详情时才返回
正文；角色学习或准备外部法术时，规范化快照才进入战役的 `spells`。因此已经
学习的法术在外部文件缺失或更新后仍保持不变，审计快照也不会为每次操作重复
携带全部 356 篇正文。

外部行以“来源 + 规范化名称”的 UUIDv5 作为稳定 ID。战役内已有同名 SRD
结构化法术时优先使用战役版本。自然语言解析只将单一、高置信度效果标为自动；
专注、多目标、持续、召唤和歧义效果统一降级为手动裁定。

## 多职业施法

`class_levels` 保存十二核心职业等级，`spell_repertoire` 按“法术 ID + 来源职业”
保存已知、法术书、准备或玄奥秘法状态。`spells` 仍是当前可施放法术 ID 的兼容
投影，供旧 Web 页面使用。

普通多职业法术位保存在 `spell_slots`，邪术师契约位和玄奥秘法分别保存在
`pact_slots`、`mystic_arcanum`。职业调整必须重新验证全部来源和容量；共享位
与契约位同时可用时禁止隐式选择。规则覆写必须提供原因并进入操作请求审计。

## 写事务

`CampaignStore.mutate` 的执行顺序：

1. 使用 `BEGIN IMMEDIATE` 取得 SQLite 写锁。
2. 读取当前快照并补齐旧版本字段。
3. 深复制快照，在副本上执行业务规则。
4. 推进修订号，以旧修订号为并发条件更新战役。
5. 在同一事务写入请求、修改前快照和修改后快照。

规则抛出异常时整个事务回滚。例如购买时即使已经扣款，后续负重校验失败也
不会留下部分修改。

## 撤销语义

撤销是补偿操作，不是删除操作。系统只允许撤销当前战役最后一次有效修改；
目标操作后若已有其他写入，则返回冲突。撤销本身也有独立操作 ID 和审计记录。

## 扩展约束

新增写能力时应同时完成以下事项：

1. 在 `WorkshopService` 中实现校验和状态变更，并调用 `store.mutate`。
2. 在 `mcp_server.py` 增加中文工具说明，明确 ID、枚举和单位。
3. 若需 Web 调用，将方法名加入 `web.py` 的 `COMMANDS` 白名单。
4. 为成功路径、规则拒绝和事务回滚增加针对性测试。
5. 更新 README 的功能范围或限制，避免文档承诺超过实现。

目录数据应保留来源和许可字段。不要将规则实现绑定到来源未经确认的数据文件，
也不要导入 SRD 以外的 Product Identity 内容。

## 测试策略

- `test_service.py`：领域规则、不变量和事务原子性。
- `test_state.py`：旧快照兼容与默认状态。
- `test_dice.py`、`test_currency.py`：纯函数和边界输入。
- `test_web.py`：HTTP 状态映射、命令链路和前端托管。
- `test_mcp.py`：关键 MCP 工具注册契约。

随机规则通过注入随机源测试。新增战斗规则时应断言结构化事件，而不只检查最终
HP，以保证 AI 可以审计骰点和规则推导过程。
